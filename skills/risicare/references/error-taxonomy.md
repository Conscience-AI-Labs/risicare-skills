## What the SDK emits

The released SDKs, `risicare` 0.5.0 (PyPI) and `risicare` 0.8.0 (npm), write `error.code` on each span that ends with an error. They emit 19 of the codes in this file, and the same code for the same error. The SDK never emits the other 135 codes.

The SDK uses three steps. The first match wins.

1. The `classify_error()` keyword rules of `risicare-core` (the Keywords column above), on the error message in lower case. They give 17 codes.
2. Five SDK rules, on `<exception type name> <message>` in lower case. Only the third rule adds a code.
3. The fallback `TOOL.EXECUTION.CRASHED` (severity 5), when no rule matches. A `ValueError` or a `KeyError` with no keyword gets it.

| SDK rule (regular expression) | Code |
|---|---|
| `timeout\|timedout\|aborted` | `TOOL.EXECUTION.TIMEOUT` |
| `rate.?limit\|\b429\b\|too many requests` | `TOOL.EXECUTION.RATE_LIMITED` |
| `connection\|econnrefused\|econnreset\|enotfound\|fetch failed\|unreachable\|broken pipe` | `TOOL.EXECUTION.DEPENDENCY_FAILED` |
| `\bauth\|unauthorized\|forbidden\|permission\|\b401\b\|\b403\b` | `TOOL.INVOCATION.PERMISSION_DENIED` |
| `json\|syntaxerror\|unexpected token\|decodeerror` | `PERCEPTION.PARSING.JSON_INVALID` |

So the rules give 18 codes, and the fallback is the 19th. Measured on 2026-10-04 with the packages from the registries: 170 errors (the 147 rows of the SDK's shared fixture `error-code-parity.json` at `cce1df4`, and one probe for each rule) were raised in a span of each SDK and read back from a loopback sink. Python 0.5.0 emitted 19 distinct codes, JavaScript 0.8.0 emitted 19, and the two disagreed on 0 errors. 52 of the 147 fixture rows got the fallback. Do not expect any other code from the SDK.
